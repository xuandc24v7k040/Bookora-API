# Local semantic search (P1)

Search uses one local E5-small q8 model, product vectors and the existing SQL list/filter/hydration path. Home, live suggestions and legacy Related do not use AI. Search is public and does not read customer signals. Model files are provisioned separately and never downloaded by a request or worker.

1. Use Node 22 (tested with 22.22.2), install the lockfile and run `npm run build`.
2. Run `node scripts/provision-ai-model.mjs`. This downloads the pinned public revision and verifies every SHA256. To reuse a verified cache, pass `--from <directory>`; optionally pass `--destination <directory>`.
3. Set process environment `SEMANTIC_SEARCH_ENABLED=true` and `AI_MODEL_PATH=<model directory>`, then use the existing Nest dev or compiled production start command. Default is OFF. Relative model paths resolve from the backend working directory. Do not paste credentials into commands or change existing credentials.

One internal child process owns the model and loads once asynchronously. It has no HTTP listener or separate deployment. This isolates native ONNX crashes and hard cancellation from Nest. Commerce readiness does not wait for it. Missing/corrupt artifacts, queue pressure or an inference deadline use keyword fallback. An unavailable worker stays unavailable until application restart, preventing retry storms. Queue capacity is five including the running task. Queries have a one-second deadline including waiting; background document jobs have a five-second deadline including waiting. Search uses SQL while a repair is running, avoiding repeated metadata scans or query jobs competing with the build. Timed-out work kills its owning process instead of accumulating native tasks. Shutdown waits for process exit. There is no index persistence, cron, polling, Redis, schema change or external inference.

The first eligible request reconciles a minimal committed public projection and starts one sequential document repair. Search temporarily uses SQL until its full vector snapshot is valid. Subsequent eligible reads reuse unchanged fingerprints and revalidate before consuming query scores. Fingerprints include all selected source content and relation values plus document/model identity; price, stock, reviews and promotions are excluded. Late jobs recheck committed content/visibility before publication. Overlapping reads can fall back; fresh post-commit reads never trust detected stale vectors. Hydration checks visibility/filters again and makes at most one lexical retry if a candidate disappears.

`AiModule` exports `AiCatalogRepository`, `ProductVectorIndex`, `EmbeddingService` and `SemanticSearchService`. A future consumer can inject the shared current public projection, call `beginRead()`/`reconcile()` and obtain `snapshot(products)` without calling Search. The snapshot supplies only fingerprint-matching vectors; `EmbeddingService.embed()` supports query/document inputs. P2 must reuse these interfaces and the same model; P2 is not implemented here. Internal diagnostics are in-process only and contain aggregate counters/fingerprints, never customer queries or public raw scores.

The frozen representation allocates token budgets to real fields, excludes generic editorial boilerplate, uses E5 prefixes, mean pooling and L2 normalization. Threshold is 0.845; SQL exact/title-prefix/phrase and author/publisher matches are protected. Semantic candidates do not pad a result page. Natural-language budgets, negation and availability are not hard filters: existing explicit controls remain authoritative. Consult the official P1 handoff for measured quality, limitations and verification status; this setup document is not a verification claim.
